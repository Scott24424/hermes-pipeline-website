Goal 01

안전한 격리된 작업 환경 (Worktree)

Human-in-the-loop

AI 모델이 코드를 작성하는 동안, 시스템의 안정성을 보장하기 위해 로컬 Worktree의 격리된 브랜치에서 모든 작업이 진행됩니다.

운영 시스템과의 분리 (Isolation): AI가 생성하는 코드는 즉시 Live 시스템(운영 서버)에 반영되지 않습니다. 대신, Git Worktree를 활용한 별도의 브랜치에 저장됩니다. 이렇게 하면 AI가 치명적인 버그를 만들더라도 운영 환경에는 전혀 영향을 주지 않습니다.

직접 테스트 가능 (Direct Testing): 작업이 격리된 브랜치에 저장되므로, 사용자는 메인 브랜치를 건드리지 않고 해당 브랜치로 이동(또는 해당 Worktree 디렉터리 접근)하여 수정된 시스템을 직접 로컬에서 실행해보고 테스트할 수 있습니다.

Human-in-the-loop 검토: AI가 PR(Pull Request)을 생성하면, 사용자가 코드를 직접 검토하고 승인(Approve)해야만 배포 파이프라인(CI/CD)을 거쳐 Live 시스템에 반영됩니다.

주요 안전 장치

  • Read-only Nodes: 기획 및 리뷰 에이전트는 코드 수정 권한이 원천 차단됨
  • Sandbox Environment: 격리된 브랜치에만 쓰기 가능
  • Manual Approval: 최종 배포 전 사람의 승인 필수
Architecture

진행 아이디어 및 아키텍처

사용자와 Hermes Agent 사이에 복수 위임 구동자(Dual Delegated Drivers: Claude Code Opus 5.5 / Codex GPT-6.1-sol)를 배치하여, 파이프라인 지휘와 기계적 판단을 자율 구동합니다. 특정 AI 모델의 구독 한도나 장애 시에도 구동자를 상호 교대(규칙 3.7조)하여 무중단 운영이 가능하며, 핵심 의사결정은 인간이 최종 통제하는 Human-in-the-loop 원칙을 견고하게 유지합니다.

위임 구동자는 Hermes를 비대화형 세션으로 실행하고, 완료 직후 작업 공간의 보고서, 운영 원장, 검사 증거를 직접 읽고 분석하여 후속 조치를 스스로 판단하거나 사용자에게 에스컬레이션합니다.

⚡ 이중 위임 구동 체계 (Claude Code ↔ Codex 상호 인수인계)

위임 구동자는 hermes chat -Q -s dev-pipeline --resume <세션> --query-file <지시파일> 형태로 비대화형 실행을 수행합니다. 지시마다 [위임 구동: Claude Code] 또는 [위임 구동: Codex] 식별 표식을 달아 Hermes 원장에 기록하며, 파일 기반 인수인계 체계(Docs/hermes-driver-handoff.md)를 통해 구동자가 바뀌어도 작업 연속성을 완벽하게 보장합니다.

🤖 자율 위임 범위 (구동자 자율 처리)

  • 호출 예산 봉투(Envelope) 관리: 슬라이스 단위 호출 상한(25~63회) 내에서 단계별 최적 배분 및 일일 상한($40) 추적
  • 기계적 결함 자동 교정: 코드 본문 왜곡 없이 엄격한 대조로 검증되는 패치 오류(git apply --recount)나 추출 형식 오류 즉시 해결
  • 사전 승인된 모델 교체: 출력 한도 초과 등 실패 시 규칙표에 의거하여 승인된 대체 모델(예: Gemini 3.8 Flash, Opus 4.6 Thinking) 투입
  • 명세 빈틈의 기술적 보완: 요구사항·보안에 영향 없는 기술적 표기나 형식(포인터 표현, 오류 형식 등)을 자율 결정하고, 모든 결정은 결정 원장(delegated-decisions.md)에 투명하게 기록

👤 사용자 에스컬레이션 (Human-in-the-Loop)

  • 예산 및 비용 상한: 슬라이스별 봉투 예산 소진 또는 일일 관측 비용 상한 도달 시 작업 중단 후 승인 요청
  • 요구사항 및 기준 변경: 프로젝트 범위 축소/확대, 기능 스펙 변경, 수용 기준(Acceptance Criteria) 수정
  • 미승인 모델 및 설정 변경: 규칙표에 없는 임의 모델 투입, roles.json 및 파이프라인 프레임워크 설정 변경
  • 연속 4회 실패 방어선: 동일 단계에서 4회 연속 실패 발생 시 무한 루프를 방지하고 인간에게 즉각 보고 (규칙 4.5 개정)
  • 최종 판정 및 배포: 슬라이스 결과물의 최종 수용 판정과 메인 브랜치 병합(Merge) 및 운영 Live 시스템 배포
