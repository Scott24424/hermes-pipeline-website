Hermes Pipeline

Multi-Agent AI Automation

AI Agents for Reliable Development

Hermes Pipeline orchestrates multiple LLMs (Claude, Codex, Antigravity) to design, build, and verify software safely through isolated Worktrees and Human-in-the-loop approvals.

Goal 01

안전한 격리된 작업 환경 (Worktree)

Human-in-the-loop

AI 모델이 코드를 작성하는 동안, 시스템의 안정성을 보장하기 위해 로컬 Worktree의 격리된 브랜치에서 모든 작업이 진행됩니다.

운영 시스템과의 분리 (Isolation): AI가 생성하는 코드는 즉시 Live 시스템(운영 서버)에 반영되지 않습니다. 대신, Git Worktree를 활용한 별도의 브랜치에 저장됩니다. 이렇게 하면 AI가 치명적인 버그를 만들더라도 운영 환경에는 전혀 영향을 주지 않습니다.

직접 테스트 가능 (Direct Testing): 작업이 격리된 브랜치에 저장되므로, 사용자는 메인 브랜치를 건드리지 않고 해당 브랜치로 이동(또는 해당 Worktree 디렉터리 접근)하여 수정된 시스템을 직접 로컬에서 실행해보고 테스트할 수 있습니다.

Human-in-the-loop 검토: AI가 PR(Pull Request)을 생성하면, 사용자가 코드를 직접 검토하고 승인(Approve)해야만 배포 파이프라인(CI/CD)을 거쳐 Live 시스템에 반영됩니다.

주요 안전 장치

  • Read-only Nodes: 기획 및 리뷰 에이전트는 코드 수정 권한이 원천 차단됨
  • Sandbox Environment: 격리된 브랜치에만 쓰기 가능
  • Manual Approval: 최종 배포 전 사람의 승인 필수
Architecture

진행 아이디어 및 아키텍처

사용자와 Hermes Agent가 상호작용하며, Pipeline이 각 단계별 AI 모델에게 작업을 지시합니다. 중요한 점은 AI가 모든 것을 알아서 끝내는 것이 아니라, 각 주요 단계마다 사용자와 지속적으로 의사소통한다는 점입니다.

예를 들어 기획/설계가 끝나면 사용자에게 "이 스펙대로 구현할까요?"라고 승인을 요청하고, 치명적인 리뷰 결과가 나오면 수정 방향을 제안하고 확인받습니다.

Stages

파이프라인 단계 상세

Phase 1

기획 및 설계

요구사항을 바탕으로 스펙을 정의하고 구조를 설계합니다. 대규모 작업의 경우 구현 전 사용자에게 스펙 승인을 요청합니다.

Phase 2

구현 및 테스트

테스트 코드를 먼저 작성하고(TDD), 이를 통과하는 제품 코드를 격리된 환경에 작성합니다.

Phase 3

리뷰 및 수정 루프

버그, 보안 취약점을 검사합니다. 치명적 문제 발생 시 루프를 멈추고 사용자에게 피드백을 요청합니다.

Human-in-the-Loop AI Development

모든 프로세스는 사용자의 통제 하에 이루어집니다. 직접 코드를 테스트해보고 최종 결정은 인간이 내립니다.
