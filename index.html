Hermes Multi-Agent Pipeline

3개 AI 공급사의 CLI를 결합하여 터미널에서 동작하는 완전 자동화된 무인 개발 파이프라인

목적 및 목표

Hermes Multi-Agent Pipeline은 기계적인 코드 작성 및 리뷰 과정을 AI 에이전트들이 스스로 분담하여 처리하는 자동화된 소프트웨어 개발 공장을 구축하는 것을 목적으로 합니다.

  • 목표 1. 전문화된 역할 분담: Claude(기획/설계/리뷰), Codex(구현), Antigravity(테스트/보안 리뷰) 등 각 모델이 가장 잘하는 영역에 집중하게 합니다.
  • 목표 2. 인간 개입 최소화: CLI 실행, Rate Limit 대처, 예외 처리 및 모델 폴백(Fallback)을 파이프라인 셸 스크립트 단에서 100% 자동화합니다.
  • 목표 3. 무결성과 보안 보장: 테스트 영역과 프로덕션 코드 영역의 파일 쓰기 권한을 엄격히 분리하고, 금지된 옵션을 차단하는 Guard 시스템을 도입하여 코드를 보호합니다.
  • 목표 4. 운영 시스템(Live) 안정성 보장: AI의 개발 영역(로컬 Worktree)과 실제 서비스 운영 영역을 완벽하게 분리합니다. AI가 작성한 코드는 철저한 격리 환경에만 커밋되며, 최종 시스템 반영은 인간의 검토 및 수동 배포 과정을 거쳐야만 이루어지므로 운영망의 무결성이 100% 보장됩니다.

진행 아이디어 및 아키텍처

이 시스템은 크게 Hermes(지휘관)와 Pipeline 스크립트(실행자), 그리고 각 AI 모델 CLI(작업자)로 구성됩니다.

  • 역할 분리 (`roles.json`): 각 개발 단계(Plan, Design, Spec, Implement, Test, Review 등)별로 어떤 모델을 호출할지 체인(Chain) 형태로 정의합니다. 메인 모델이 실패하거나 한도 초과가 발생하면 자동으로 예비 모델로 전환됩니다.
  • 명령어 생성 및 제어: `agent-run`, `command.js` 등 자체 개발된 Node.js 랩퍼(wrapper)를 통해 AI의 터미널 호출을 가로채어 시간 초과(Timeout), 토큰 비용 측정, 출력 검증을 수행합니다.
  • 격리된 파일 조작 (Guard): 코드를 수정하는 권한은 엄격히 통제됩니다. Codex는 작업 트리(Workspace)만 수정할 수 있고, Antigravity(agy)는 테스트 폴더(`tests/`)만 수정할 수 있도록 분리하여 상호 코드가 훼손되는 것을 방지합니다.

파이프라인 상세 소개 (Pipeline Stages)

전체 개발 사이클은 다음과 같은 단계로 순차적으로 혹은 피드백 루프를 돌며 진행됩니다.

  1. 기획 및 설계 (Plan & Design): 요구사항을 바탕으로 스펙을 정의하고 구조를 설계합니다.
    * 대규모 작업(L)의 경우, 구현으로 넘어가기 전 사용자에게 스펙 승인을 요청합니다.
  2. 테스트 작성 (Tests): 실제 제품 코드가 작성되기 전, 명세에 따른 테스트 코드를 먼저 작성합니다(TDD).
  3. 구현 (Implement): 스펙과 테스트 코드를 바탕으로 실제 동작하는 애플리케이션 코드를 작성합니다.
  4. 코드 및 보안 리뷰 (Review): 구현된 코드를 바탕으로 버그, 구조, 보안 취약점을 검사합니다.
  5. 수정 피드백 루프 (Fix Loop): 리뷰 결과에서 문제(Blocker)가 발견되면, 다시 구현 단계로 돌아가 코드를 수정합니다.
    * 해결 불가능한 치명적 문제 발생 시, 루프를 멈추고 사용자에게 방향성을 묻습니다.
  6. 판정 및 병합 (Judge & Accept): 최종적으로 코드가 기준을 통과하면 확정하고 커밋을 생성합니다.

단계별 AI 모델 사용 (Roles)

파이프라인은 roles.json에 정의된 체인에 따라 각 업무를 가장 적합한 모델에게 할당하며, 한도 초과(Rate Limit) 등 실패 시 다음 후보 모델로 폴백(Fallback)합니다. 아래는 L/M/S 등급에 따른 대표적인 역할 분담 표입니다.
